# Vulkan NR + Universal MFG

The shared Windows x64 runtime supplies a Vulkan DLSS-SR-to-DLSS-G integration, native Vulkan Neural Rendering and an in-game rtxForge panel. BG3 and RDR2 use the same `fgvk.dll`, NR forwarder, Streamline runtime and Universal MFG Unlocker. One identical Bink proxy preserves each game's original DLL and forwards the union of named exports. Incompatible ordinal imports are refused. Game profiles select application identity and input conventions; RDR2 requires observed resource layouts.

Use the existing **Universal Experimental** compatibility badge. GPU eligibility, component loading, NR composition and generated-frame output are separate states. RTX 20 and RTX 30 are opt-in trial routes with no rtxForge hardware verification. RTX 40 uses the Universal MFG unlock. RTX 50 uses NVIDIA's native MFG capabilities and needs no hardware unlock; games missing FG still need this Vulkan integration. NR hardware/model support is determined by the selected model and driver.

NR runs after a successful, identified native DLSS-SR evaluation on the same command buffer, before the game's later post-processing and HUD. Feature ownership excludes FG and NR evaluations and invalidates released handles. NR adds its required supported extensions at device creation; missing extensions disable NR without submitting unsupported device extensions. The initial route uses an explicit white point, with no unknown-layout exposure-image access. NR counters increase only after successful composition recording. Streamline's actual displayed-frame counts provide independent FG/MFG telemetry.

At startup, NR waits for 120 native DLSS-SR presentations spanning at least three seconds. Loading gaps and failed presentations reset that warm-up. This also allows later panel activation immediately after a stable native startup. Single-device image acquisition through `vkAcquireNextImage2KHR` uses Streamline's tracked acquisition route; extension chains and multiple-device masks retain their native route.

Streamline's latency delay imports bind to the bundled private latency DLL before device creation. A game's older latency DLL and its imports remain untouched. Missing exports or mixed plugin paths refuse this integration and leave native Vulkan instance creation available. The overlay uses only the game's existing window and surface; its ImGui backend capabilities exclude secondary OS windows.

The Vulkan host draws the canonical rtxForge ImGui panel with its Inter faces, controls and saved shortcut (Delete by default). Compact statistics beside the feature toggles distinguish NR GPU time and actual rendered/displayed FG output from requested multipliers. Show live statistics is a shared saved panel preference. Unsupported backend controls are disabled. The shared font loader uses the same stb_truetype rasterizer and dynamic atlas approach as the Universal MFG panel. The pinned Universal MFG component retains its advanced Backspace panel. Its private configuration follows the shared provider's multiplier requests. A requested count or loaded component does not establish the effective displayed multiplier.

The Windows helper discovers active Vulkan installations from their external recovery journals, verifies the loader/provider hashes and checks the complete running executable path before connecting. It supplies the DLSS file-ownership lights and caches the game's saved or artwork-derived accent, including experimental installations outside the ordinary provider scan. File status is separate from live NR/FG telemetry. Vulkan helper preset save/reset is not yet available; those buttons remain disabled while in-game live controls work.

`build.py` stages exact dependency Git objects into a new directory outside the checkout and emits `build.cmd`. Run that command from its output directory using the installed MSVC x64 tools. It builds the shared runtime and NR forwarder and runs native host checks. `loader/Build-Loader.ps1 -Profile universal -OutputDirectory <new-directory> -Test` builds one common loader and exercises both original export tables, startup, forwarding, small stacks, DX11 isolation and missing-provider behavior. It also checks unchanged executable entry bytes and no provider initialization inside a TLS callback. Startup follows the game's first safe Vulkan loader lookup through its GetProcAddress import; it does not patch the executable entry point. A missing trigger leaves Bink forwarding active. The guarded startup approach follows Ultimate ASI Loader; its MIT notice accompanies the loader.

`package.py` creates a local gameplay candidate from those builds, the pinned BG3 Streamline archive, the pinned Universal MFG archive and a user-supplied `nvngx_dlssnr.dll`. The NR model is excluded from distributable builds. Its local candidate manifest pins every file and both loaders. Required upstream legal notices and the source receipt accompany the runtime. The combined runtime is GPL-3.0-only; the MIT sources, third-party runtime files and user-supplied model retain their own terms.

Use `scripts/vulkan_dlssg_provider.py` with `--profile bg3|rdr2 --manifest <candidate.json>`, `--game`, `--archive`, `--loader` and explicit `--experimental`. Review/install/repair/restore keep their external journals and hashes. Restore the earlier standalone BG3 provider before changing to this recipe. An unmanaged loader, conflicting installation, modified immutable payload, running game or changed review is refused. A fully restored candidate can be replaced by a newer file inventory after its old destinations are checked; the previous journal and its evidence references remain in recovery storage. An active inventory change requires restoring its original candidate first. Mutable NR/MFG settings and runtime evidence are preserved during repair/restore; unrelated game files and mods remain outside the provider's ownership.

The source manifest keeps runtime verification and default promotion false. Qualification must identify the exact binaries, model, driver, GPU and settings and measure NR execution together with displayed FG/MFG output for each game. Shared source, a successful build, host fixtures and upstream GPU reports do not establish gameplay support.
