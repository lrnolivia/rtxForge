rtxForge Beta 1 brings the Linux and Windows apps, Game Mode and in-game overlay/panel features together in a public testing release.

New in build 1.0.0-beta.12:

- **Optional RenoDX HDR installs automatically** from each matching game's desktop Tools page. rtxForge finds the game-specific add-on and downloads the verified full add-on ReShade runtime. Managed OptiScaler loads it where supported; existing Feeder/ReShade hooks are reused; eligible standalone games get the appropriate DirectX or OpenGL hook. No stack or mod file needs to be supplied.
- **HDR has separate install, update and removal records.** Reused NR/MFG files remain owned by their existing package, including shared Windows/Linux installations. Removing HDR restores its loader setting while keeping later tuning. Standalone Proton hooks include a recorded DLL override, and new ReShade settings follow the saved menu and welcome preferences.
- **Side-loaded ReShade settings no longer change a verified OptiScaler proxy's identity** during subsequent repair.
- Windows Control Resonant was checked in a fresh HDR10 startup and 3D scene with live NR evaluation, three generated frames per rendered frame and working glass overlay controls. ME2 package installation/removal and Feeder reuse were verified; its EA launcher prevented a live game check. Other games and Proton HDR remain unqualified. Vulkan HDR layer setup and external-only mod downloads are not available in this build. Game Mode shell work remains deferred.

New in build 1.0.0-beta.11:

- **Feeder support packages download automatically**, with pinned archive and file verification. Normal installation no longer asks you to supply a stack. Advanced local overrides remain optional.
- **Overlay settings match the glass overlay** in desktop and Game Mode: illustrated layout choices, Clear/Light/Dark appearance and text size share the current settings. Overlay scale stays in-game, where its effect is visible. Experimental font, material and toast-shape controls stay in the styling prototype. Clear remains the default.
- **Overlay refresh results are visible**, with updated, current and blocked games and a detailed report available from Settings. Counts survive retries; unfinished games remain visible.
- **Game Mode uses matching Phosphor icons** on Windows and Linux, drawn from one shared symbol map.
- **Shared Windows/Linux installations retain their identity and recovery data** when the other OS updates a managed package. Verified production Vulkan runtimes are preserved, missing owned files can be recovered, and shared files remain readable. Unknown or changed files still require an explicit repair review.

New in build 1.0.0-beta.10:

- **A new glass overlay** brings Sidebar, Advanced and Bottom Bar layouts, textured translucent surfaces, blur, adaptive Clear text and shadows, and smoother window motion. Clear is the default; Light and Dark keep their own material settings. Appearance includes text size, main font, overlay scale and detailed material controls. Your choices remain editable.
- **Live session details** expand from the compact status card. Short MFG and NR cards show the measurements reported by the installed package. Advanced opens with the expanded Overview. Unsupported measurements remain unavailable.
- **Tuning and Settings** include undo/redo, per-field and section resets, named game presets, explicit on/off or preset comparisons, supported pass overrides and the existing overlay options. The slim welcome toast shows the actual shortcut, and the same notification style reports live changes.
- **Managed overlays refresh with the app update** on Windows and Linux. Packages are verified before installation, running games are retried, and game originals, user tuning and compatible saved presets are preserved. Foreign or modified files are retained for repair rather than overwritten.
- The new renderer supports DX11/DX12 SDR and supported scRGB/HDR10 output. Other rendering routes retain the established panel while their new renderer integration is being validated.

New in build 1.0.0-beta.9:

- **Automatic application updates** download in the background and verify SHA-256 and size before becoming ready. Windows setup installations, Linux AppImages and standard user/system Flatpaks install on normal exit; **Restart to update** reopens the same interface. Running games or file operations postpone installation. The setting is on by default and can be turned off in desktop Settings or Game Mode.
- Windows applies the verified installer quietly in the existing installation folder. Failed setup attempts are reported on the next check. Portable Windows copies open the ZIP download page; custom Flatpak installations stay with their software manager. Downloads, offline failures and invalid cached files never replace the running installation.

New in build 1.0.0-beta.8, on Windows and Linux alike:

- **Start Test / Finish Test checks each part of every installed package.** Package ownership, settings, panel shortcut, Proton/CUDA where applicable, the game hook, NR, MFG, panel attachment and helper appear as separate results with evidence and suggested next steps. Live Skynizz snapshots, Feeder model-evaluation logs, Vulkan NR/frame-generation statistics and other OptiScaler logs supply the evidence their packages actually expose. Missing telemetry says **not reported** and never becomes a pass. Old log bytes and stale snapshots cannot establish a new result.
- **View results** is available on each game's Overview in desktop and Game Mode. The suggested Working or Problem result stays yours to accept. Bug Report suggests NR/MFG answers from observed execution and includes the test's findings and fixes; you can correct them, and still describe what you saw. Runtime execution does not establish picture quality.

New in build 1.0.0-beta.7, on Windows and Linux alike:

- **Bug Report sends the report for you.** Pick the game, say what happened, mark NR and MFG as Worked, Didn't work or Didn't test, and press **Send Report**. It becomes an issue on rtxForge's GitHub, with no GitHub account needed, and you get the issue number back. Logs, on by default, go privately to the maintainers and aren't public. What rtxForge detected sits folded under "Details we'll include", and **See what's sent** shows the exact text and logs first. A copy is still saved in `Documents/rtxForge Reports`, so nothing is lost if sending fails.

New in build 1.0.0-beta.6:

- Linux Game Mode has **Bug Report** too: on every game's header, in a Testing group on its Overview, and in Settings › About. Choices change with A or Left/Right and text uses Steam's on-screen keyboard; you review the redacted preview before the ZIP is saved, then open the prefilled form. Notes in Game Mode is just your notes.

New in build 1.0.0-beta.5, on Windows and Linux alike:

- **Bug Report** has its own button on every game, next to Restore Original Files, and in Settings › About. A game's Overview now holds its test result and test session; Notes is just your notes.
- **Add rtxForge to Steam** is the first setting in Gaming Mode, in desktop Settings and in Game Mode, highlighted until rtxForge is in your Steam library.
- A game's Overview shows the package route it uses and names any other compatible ones, instead of every route rtxForge knows.

New in build 1.0.0-beta.4:

- **Bug Report** fills in the same report as the website. Your OS, graphics card and driver, rtxForge version and each game's installed package are filled in for you; you choose what you saw in game. Pick one game, a few or the whole library. Logs are optional: you review the exact redacted text before rtxForge saves a ZIP to `Documents/rtxForge Reports`, then open a prefilled GitHub report or add the ZIP to an existing one. Nothing is uploaded for you.
- Windows catches up with the Linux app: one executable chooser for scans and reviews, independent package checks for each game, experimental Feeder NR for DirectX 9, DirectX 10 and 32-bit DirectX 11 games with exact restore, and an initially unchecked, offline-only acknowledgement for compatible games with anti-cheat.
- The in-game panel and welcome toast are easier to read in Light, Multi-Frame Generation statistics count the frames Streamline actually presented, and inZOI draws the panel above its own interface.
- Linux: an installed AppImage starts the in-game panel helper right away and at sign-in, so the panel works with rtxForge closed, in Desktop and Game Mode. RTX 50 cards can use their own Multi-Frame Generation under Proton (not yet verified).

Earlier builds made library-wide installs much lighter:

- The engine no longer keeps a copy of each game's NR model in memory. Large package and model files stay on disk and are verified as they are copied, so memory stays flat instead of growing by hundreds of megabytes per game.
- Reviews read each game file once. Executables are no longer read in full to find their imports, unchanged files are not hashed again before installing, and files that already match are verified in place instead of rewritten. This removes most of the disk load that could stall the system during large installs.
- Progress keeps one style for a whole step: the counter and bar no longer switch to "Preparing…" or jump back while a package is verified, and long game titles are trimmed instead of widening the progress window.

For Windows x64, choose the installer or extract the portable ZIP and run `rtxForge.exe`. The installer includes the private Python runtime and engine, and preserves existing settings and original-file backups. Windows on Arm has a separate ARM64 installer; the bundled native game runtimes require compatible games and hardware. SHA-256 files accompany each download.

For Linux x86_64 the targets are Bazzite, SteamOS and CachyOS. The AppImage runs on Bazzite and CachyOS: allow it to run in its file properties and open it (it uses the system's Python 3, GTK4, libadwaita 1.7+ and PyGObject; on CachyOS install `python-gobject` and `libadwaita` first). The Flatpak (`rtxForge-<version>-x86_64.flatpak`) runs on all three and is the one to use on SteamOS: it brings its own GTK4 and libadwaita from Flathub's GNOME runtime. Install it with Discover or GNOME Software, or `flatpak install --user` on the downloaded file. It checks running games, Steam and anti-cheat on the system itself through Flatpak's host access and the system's Python 3, and refuses changes if it cannot. The Linux Beta brings the native GTK app and Game Mode, the in-game panel with its background helper, and Skynizz NR + MFG under Proton:

- **Adapt to Linux** sets up games already installed with rtxForge on Windows on a shared drive, in one click for the whole library or per game. It never changes the game folder or the Windows install, and games show Windows and Linux marks once set up for both.
- Frame generation under Proton needs a Proton build with NVIDIA's CUDA library, such as Proton-GE. A game must have been started once with Proton, or Steam closed, before it can be set up.
- The existing Linux updater channel keeps working alongside this release.

Known testing limits:

- Controller scrolling in long modal lists can intermittently fail to move the list.
- Steam Controller reports and scroll routing have been checked, but physical right-stick feel still needs broader hardware testing.
- The Light overlay has not yet completed visual verification inside games, including HDR output.
- Linux packages include the matching native bridge and preset protocol. Vulkan games (Baldur's Gate 3, Red Dead Redemption 2) have not yet been verified under Proton; their glass renderer integration is not available yet.
- RTX 50 Multi-Frame Generation under Proton and the DirectX 9 and 10 Feeder routes have not yet been verified in moving gameplay.

Report issues with **Bug Report** in the app or at [loew.fi/rtxforge/report](https://loew.fi/rtxforge/report): include the game, your OS version, controller and input mode, and the steps that reproduce them. Close games before reviewing and installing changes; use Restore Original Files to remove installed features.
