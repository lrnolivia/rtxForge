Set up and use rtxForge.

Get the app for Linux.

Choose your operating system on the downloads page. It shows the packages actually published for each channel.

Beta
The regular public testing release. Start here.
Development
A moving release with the latest changes. Expect more frequent updates and unfinished features.

A channel may say coming soon until its release and your OS package are published. The old continuous release remains for existing Linux updater compatibility; it is separate from the new Beta and Development channels.

Linux x86_64 with a working NVIDIA driver. Package-specific requirements are listed with each release.

Flatpak (recommended for SteamOS)

  1. Download the .flatpak from the selected release.
  2. Open it with Discover or GNOME Software, or run flatpak install --user with the downloaded file. Flathub provides the GNOME runtime it needs.
  3. Open rtxForge from your app menu.

The Flatpak brings its own GTK4 and libadwaita, so it works on SteamOS and any system without them. It still checks running games, Steam and anti-cheat on your system through Flatpak’s host access and the system’s Python 3, and refuses changes if it cannot. It is attached to the release, not listed on Flathub.

AppImage (Bazzite and CachyOS)

  1. Download the AppImage from the selected release.
  2. In your file manager, open its properties and allow it to run as a program. Open the AppImage.
  3. Keep it somewhere permanent if you add a launcher or Steam shortcut. Moving it later can break that shortcut.

The AppImage uses host Python 3, GTK4, libadwaita 1.7+, and PyGObject. If it will not open, check those dependencies and any FUSE error. A Bazzite filename identifies the build; the app checks host capabilities rather than just the distribution name.

Keep space for runtime downloads and original-file backups. Linux runtime preparation needs at least 4 GiB free at the app’s state location.

Installer

  1. Download the x64 installer. If it arrives as a setup ZIP, extract it first.
  2. Run the setup .exe and follow its prompts.
  3. Open rtxForge from the Start menu. Packaged builds include the app runtimes and Python; no development SDK is needed.

Portable

Download the portable Windows ZIP, extract the entire archive, then open rtxForge.exe. Keep its companion files together. Portable skips app installation, but preferences, downloaded runtimes, and recovery records can still live outside that folder.

Check the release’s signing and build notes. Development previews may be unsigned. Use the package from the official release and compare its checksum when one is supplied.

Choose a download

Choose your packages.

Open the Library, rescan your games, and start with one compatible title. If a game is missing, check your library locations in Settings or add its folder.

Choose a supported package in Packages, or inspect a custom ZIP. Select NR Only, MFG Only, or NR + MFG, then choose a compatible provider. Available packages and combinations depend on your build and operating system.

  • Neural rendering: experimental, for compatible RTX cards and supported game/provider routes. Some packages need a separate compatible model file; the review tells you what is missing.
  • Multi-frame generation: supports RTX 20, 30, and 40 series on compatible routes. A selected multiplier is a request, not a promise of the same multiplier in net FPS.
  • Custom packages: inspect the source and proposed files. A checksum verifies the download’s integrity, not its safety or game compatibility.

Already have a managed install? Use its repair or restore controls before switching provider or feature mode. If your build offers Adoption for an existing manual install, review exactly what it recognizes before letting rtxForge manage it. Unknown files should not be overwritten.

Tune presets.

Use the Presets sidebar for library defaults, then adjust an individual game from its details. Choose the NR strength, sharpening, and frame-generation settings supported by your selected package.

Save or apply the preset as shown in your build. A saved value does not prove a feature is running. Existing games may need a reviewed settings update or a restart; check the operation summary rather than assuming a library default changed every installed game.

NR starts off on new and clean installs. Choose Enable NR on launch in the install review when you want it to start enabled; its default is in Settings → Graphics. Adoption and repair preserve the recorded startup choice. You can also enable NR from the supported in-game controls.

Install into your games.

  1. Close the selected game. Avoid protected online games and anti-cheat. Keep your original-file backups.
  2. Select your games and choose Install Features. Read the provider, feature mode, downloads, file changes and any launch-setting changes in the review.
  3. Apply the reviewed operation. Let it finish, then check the result for each game. If a game is blocked, follow the reason shown instead of forcing an overwrite.

Steam can stay open for supported installation routes. If the review needs to change a Steam-managed setting or reports a running-client conflict, close Steam and review again. Keep the Proton route shown for that game.

Windows games load the selected runtime from their game files. Follow the exact executable and game/API requirements shown in the review; a launcher and the actual game executable may be different.

Built for dual boot

For supported games already set up with rtxForge on Windows on a shared drive, use Adapt to Linux for one game or the library. It prepares the Linux side without changing the Windows installation or game folder. Use a Proton build with NVIDIA CUDA support, such as Proton-GE, for frame generation; launch the game once with that Proton build, then quit before adapting.

Games on a drive shared with Linux can be adapted from the Linux app using Adapt to Linux. Keep the Windows install and recovery records; let the Linux app review its own Proton setup rather than copying launch settings between OSes.

Play.

Launch the game and enable the DLSS and frame-generation options required by your package. Start with its supported defaults, check the image and frame pacing, then tune one setting at a time.

NR startup behavior and shortcuts depend on the provider. Follow the package’s notes and the controls shown in your build. A green installed badge, saved preset, or log entry alone does not establish a visible NR effect.

Beta 1 includes the in-game overlay/panel. Set it up below before relying on a shortcut from another build. Controls and package support can differ between Beta and Development.

Set up the in-game overlay.

The rtxForge panel gives you NR and MFG controls while a compatible game is running. The game needs a supported rtxForge feature package installed first; changing an app preference alone does not install the panel.

  1. Open Settings → Overlay. Choose the rtxForge panel as your primary overlay. On Linux this choice is labelled In the game; on Windows choose rtxForge. The native-menu alternative is covered in the next section.
  2. Check Panel shortcut. Use the key displayed by your installed build. Choose Record to set a key or a Ctrl/Alt/Shift combination; Reset restores that build’s default and Disable removes the binding. Keep it separate from the game’s controls and OptiScaler’s shortcut.
  3. Choose the controls and appearance. Unified uses simple labels; Advanced uses the package’s original labels and units. Choose Dark, Light, or Follow app. The welcome message, its position, and live feature statistics have separate settings.
  4. Apply changes to installed games. Close the affected games, choose Update Overlays, inspect the per-game package, menu and shortcut changes, then apply. Restart the game to use startup and native-menu changes. On older builds without this action, follow the package’s reviewed install or repair flow.
  5. Launch one game and press your panel shortcut. Adjust supported NR/MFG controls, then use Save preset when you want to keep the tuning. Check the result in the game before moving on to other titles.

Enable Background overlay helper to keep saved presets and panel settings available after closing the manager. Start with Windows starts the helper, not the full manager. The overlay follows the compatible game you are playing. In builds that expose them, its gear opens Overlay settings and its globe opens a reviewed Global change.

Keep rtxForge running while using its background helper. Overlay preferences are written into the game’s Proton setup through a reviewed operation while the game is closed. The panel draws inside the game, so its shortcut does not need a desktop-wide key binding in Wayland or Gamescope.

For a different setup in one title, open the game’s Overlay controls and turn off Use app overlay settings. Review Update Overlays for that game. Turn inheritance back on to use the app-wide choices again.

Live statistics appear only when the installed runtime supplies them. A requested MFG multiplier, a saved preset, or a log entry is not proof of the same gain in measured FPS or visible NR quality.

OptiScaler and ReShade menus.

These are the menus provided by the installed game package. They are separate from the rtxForge panel and from the game’s own graphics menu.

OptiScaler
In Settings → Overlay → OptiScaler, enable its in-game menu and choose Insert, F8, or Disabled for its shortcut. Its intro message is a separate toggle. The original menu requires a compatible current game package and a game restart.
ReShade / Feeder
The ReShade section controls menu access separately from its welcome messages. Those welcome choices cover the ReShade guide and RenoDX welcome dialog; short loading notices are separate. Use the shortcut shown by your installed ReShade configuration.
Native MFG menu
On routes that expose it, Native MFG menu and hint enables the package’s optional advanced menu. Hiding it keeps frame generation installed and running.

Hiding a menu or its intro does not uninstall NR, MFG, or Feeder effects. You can keep native menu access alongside the rtxForge panel, or choose Native on Windows / OptiScaler menu only on Linux as the primary overlay. Review Update Overlays and restart the game after changing these choices.

Use Game Mode.

Game Mode is rtxForge’s controller interface for browsing your library, changing presets, choosing packages, and reviewing installations. The in-game overlay is a separate surface for controls while you play.

Open Settings → Gaming Mode to choose the interface, controller prompts and glyphs, scaling, and appearance. Follow the on-screen button hints when selecting games and moving through review, progress, and result screens. Close a game before applying operations that change its files.

Use Settings → Gaming Mode → Add to Steam to add rtxForge to your Steam library, then launch that shortcut from Steam’s Game Mode. Follow any request to close Steam for shortcut changes. In Gamescope, use the panel drawn inside the game; a standalone desktop companion is not a replacement for that surface.

Game Mode uses the same library, package choices, and recovery records as Desktop. Switching the interface does not install features into a game; use Install Features and its review as usual. Configure the in-game panel separately under Settings → Overlay.

Controller behavior, HDR, and VRR also depend on your hardware and display setup. Long controller-driven modal lists can have scrolling issues in Beta 1. Linux Vulkan/Proton routes and the Light overlay still have testing limits; check the release notes for your build.

Change installed games together.

Settings → Global offers a one-time NR/MFG change across installed games. Choose what to change, leave unrelated settings as they are, then review the eligible games before applying. Running games, unsupported routes, and conflicting files are excluded.

This is useful when you want to turn NR on or change MFG across existing installs. It keeps their unrelated tuning and original-file backups. New installations continue to use your Presets and install-review choices.

Update, repair, or restore.

Update rtxForge
Use the updater offered by your build or download a newer package from the same channel. An app update does not automatically reinstall game features.
Repair Feature Files
Repair a managed installation while keeping its recorded tuning. Review the changes first.
Restore Original Files
Remove the managed feature installation using its backups. Use restore before changing the installed provider or feature mode.
DLSS Files
Native DLSS DLL updates have separate backup and restore controls. See the DLSS file guide for those operations.

Keep recovery records and backups, including when using Portable or reinstalling the app. A game update or another mod may change files after installation. If restore reports a conflict, review it before replacing anything.

Something not working?

The app will not open

Check executable permission, the AppImage’s host dependencies, and any FUSE message. For a Flatpak, check the error in your software installer and that the package came from the selected release.

Extract every file from a portable or setup ZIP. Keep companion files beside the executable. Check the release’s runtime and signing notes, then report the exact message if it still fails.

A game is missing or an operation is blocked

Open Steam once, rescan the Library, and check library folders in Settings. Close the game. Read the exact conflict or missing requirement in the review; close Steam if that route asks for it. Do not replace files that the app cannot safely identify.

NR or MFG has no visible effect

Check the installed provider, feature mode, game/API support, and in-game DLSS/FG settings. Use Game Details → Tools → Diagnose NR when available. Check current package notes; installing files and evaluating a feature in a running game are different things.

The panel shortcut does nothing

Check the actual binding in Settings → Overlay, that it is not Disabled, and that the rtxForge panel is selected. Confirm a compatible package is installed into this game. Close the game, review Update Overlays, then relaunch and test that binding. Check for a conflicting game or native-menu shortcut.

Check that Background overlay helper is enabled when you want it to work after closing the manager.

Keep rtxForge open. Confirm this game has a Proton prefix from a previous launch and that the overlay review could apply its preferences while the game was closed. Use the in-game panel in Steam Game Mode rather than a desktop overlay window.

The panel opens but says it is waiting for the helper

Start rtxForge again and check the package and build used by this game. A visible panel can have a different bridge version from the app’s helper. Review the available overlay update, restart the game, and report the exact waiting message if it persists.

The Linux Beta’s preset saving/replay needs the matching game-side bridge from the release’s Windows build. Linux Vulkan games have not yet been verified under Proton; include your game API and Proton version in a report.

Menu or welcome changes did not reach an installed game

Saving an Overlay preference and applying it to a game are separate steps. Close the game, use Update Overlays for it, read the effective choices in the review, apply, then restart. Check whether that game has its own Overlay override instead of inheriting app settings. Loading banners are separate from welcome/intro toggles.

Share a beta report

Use the beta report template for your GPU, distro / OS, app format and version, feature package, game, and separate NR / MFG results. Working setups help too.

Open Settings → Recovery → Library Reports → Preview Support Report. Review and export it, then attach it on GitHub. Check for personal information before sharing.
