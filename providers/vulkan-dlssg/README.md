# Vulkan NR + Universal MFG

The shared Windows x64 runtime supplies a Vulkan DLSS-SR-to-DLSS-G integration, native Vulkan Neural Rendering and an in-game rtxForge panel. BG3 and RDR2 use the same `fgvk.dll`, NR forwarder, Streamline runtime and Universal MFG Unlocker. Their startup loaders preserve each game's original Bink DLL and use the correct export table. Game profiles select application identity and input conventions; RDR2 requires observed resource layouts.

Use the existing **Universal Experimental** compatibility badge. GPU eligibility, component loading, NR composition and generated-frame output are separate states. RTX 20 and RTX 30 are opt-in trial routes with no rtxForge hardware verification. RTX 40 uses the Universal MFG unlock. RTX 50 uses NVIDIA's native MFG capabilities and needs no hardware unlock; games missing FG still need this Vulkan integration. NR hardware/model support is determined by the selected model and driver.

NR runs after a successful, identified native DLSS-SR evaluation on the same command buffer, before the game's later post-processing and HUD. Feature ownership excludes FG and NR evaluations and invalidates released handles. NR adds its required supported extensions at device creation; missing extensions disable NR without submitting unsupported device extensions. The initial route uses an explicit white point, with no unknown-layout exposure-image access. NR counters increase only after successful composition recording. Streamline's actual displayed-frame counts provide independent FG/MFG telemetry.

The rtxForge panel uses Delete and offers NR, FG and requested 2x/3x/4x output controls. The pinned Universal MFG component retains its advanced Backspace panel. Its private configuration follows the shared provider's multiplier requests. A requested count or loaded component does not establish the effective displayed multiplier.

`build.py` stages exact dependency Git objects into a new directory outside the checkout and emits `build.cmd`. Run that command from its output directory using the installed MSVC x64 tools. It builds the shared runtime and NR forwarder and runs native host checks. `loader/Build-Loader.ps1 -Profile bg3|rdr2 -OutputDirectory <new-directory> -Test` builds each matching loader and exercises startup, forwarding, small stacks, DX11 isolation and missing-provider behavior.

`package.py` creates a local gameplay candidate from those builds, the pinned BG3 Streamline archive, the pinned Universal MFG archive and a user-supplied `nvngx_dlssnr.dll`. The NR model is excluded from distributable builds. Its local candidate manifest pins every file and both loaders. Required upstream legal notices and the source receipt accompany the runtime. The combined runtime is GPL-3.0-only; the MIT sources, third-party runtime files and user-supplied model retain their own terms.

Use `scripts/vulkan_dlssg_provider.py` with `--profile bg3|rdr2 --manifest <candidate.json>`, `--game`, `--archive`, `--loader` and explicit `--experimental`. Review/install/repair/restore keep their external journals and hashes. Restore the earlier standalone BG3 provider before changing to this recipe. An unmanaged loader, conflicting installation, modified immutable payload, running game or changed review is refused. Mutable NR/MFG settings and runtime evidence are preserved during repair/restore; unrelated game files and mods remain outside the provider's ownership.

The source manifest keeps runtime verification and default promotion false. Qualification must identify the exact binaries, model, driver, GPU and settings and measure NR execution together with displayed FG/MFG output for each game. Shared source, a successful build, host fixtures and upstream GPU reports do not establish gameplay support.
