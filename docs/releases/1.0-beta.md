rtxForge Beta 1 brings the Linux and Windows apps, Game Mode and in-game overlay/panel features together in a public testing release.

New in build 1.0.0-beta.4, on Windows and Linux alike:

- **Prepare Beta Report** fills in the same report as the website. Your OS, graphics card and driver, rtxForge version and each game's installed package are filled in for you; you choose what you saw in game. Pick one game, a few or the whole library. Logs are optional: you review the exact redacted text before rtxForge saves a ZIP to `Documents/rtxForge Reports`, then open a prefilled GitHub report or add the ZIP to an existing one. Nothing is uploaded for you.
- Windows catches up with the Linux app: one executable chooser for scans and reviews, independent package checks for each game, experimental Feeder NR for DirectX 9, DirectX 10 and 32-bit DirectX 11 games with exact restore, and an initially unchecked, offline-only acknowledgement for compatible games with anti-cheat.
- The in-game panel and welcome toast are easier to read in Light, Multi-Frame Generation statistics count the frames Streamline actually presented, and inZOI draws the panel above its own interface.
- Linux: an installed AppImage starts the in-game panel helper right away and at sign-in, so the panel works with rtxForge closed, in Desktop and Game Mode. RTX 50 cards can use their own Multi-Frame Generation under Proton (not yet verified).
- Game Mode settings put **Add rtxForge to Steam** first until rtxForge is in your Steam library.

Earlier builds made library-wide installs much lighter:

- The engine no longer keeps a copy of each game's NR model in memory. Large package and model files stay on disk and are verified as they are copied, so memory stays flat instead of growing by hundreds of megabytes per game.
- Reviews read each game file once. Executables are no longer read in full to find their imports, unchanged files are not hashed again before installing, and files that already match are verified in place instead of rewritten. This removes most of the disk load that could stall the system during large installs.
- Progress keeps one style for a whole step: the counter and bar no longer switch to "Preparing…" or jump back while a package is verified, and long game titles are trimmed instead of widening the progress window.

For Windows x64, choose the installer or extract the portable ZIP and run `rtxForge.exe`. The installer includes the private Python runtime and engine, and preserves existing settings and original-file backups. Windows on Arm has a separate ARM64 installer; the bundled native game runtimes require compatible games and hardware. SHA-256 files accompany each download.

For Linux x86_64 the targets are Bazzite, SteamOS and CachyOS. The AppImage runs on Bazzite and CachyOS: allow it to run in its file properties and open it (it uses the system's Python 3, GTK4, libadwaita 1.7+ and PyGObject; on CachyOS install `python-gobject` and `libadwaita` first). The Flatpak (`rtxForge-<version>-x86_64.flatpak`) runs on all three and is the one to use on SteamOS: it brings its own GTK4 and libadwaita from Flathub's GNOME runtime. Install it with Discover or GNOME Software, or `flatpak install --user` on the downloaded file. It checks running games, Steam and anti-cheat on the system itself through Flatpak's host access and the system's Python 3, and refuses changes if it cannot. The Linux Beta brings the native GTK app and Game Mode, the in-game panel with its background helper, and Skynizz NR + MFG under Proton:

- **Adapt to Linux** sets up games already installed with rtxForge on Windows on a shared drive, in one click for the whole library or per game. It never changes the game folder or the Windows install, and games show Windows and Linux marks once set up for both.
- Frame generation under Proton needs a Proton build with NVIDIA's CUDA library, such as Proton-GE. A game must have been started once with Proton, or Steam closed, before it can be set up.
- The existing Linux updater channel keeps working alongside this release.

Known testing limits:

- Controller scrolling in long modal lists can intermittently fail to move the list.
- Steam Controller reports and scroll routing have been checked, but physical right-stick feel still needs broader hardware testing.
- The Light overlay has not yet completed visual verification inside games, including HDR output.
- Linux: changing presets from the in-game panel needs the game's bridge to come from this release's Windows build; Vulkan games (Baldur's Gate 3, Red Dead Redemption 2) have not yet been verified under Proton.
- RTX 50 Multi-Frame Generation under Proton and the DirectX 9 and 10 Feeder routes have not yet been verified in moving gameplay.

Report issues with **Prepare Beta Report** in the app or at [loew.fi/rtxforge/report](https://loew.fi/rtxforge/report): include the game, your OS version, controller and input mode, and the steps that reproduce them. Close games before reviewing and installing changes; use Restore Original Files to remove installed features.
